# Central document-number allocator

This dependency step extracts number-format defaults from financial service code into a database registry and makes the existing sequence counter monotonic. Company/branch/year proposals and their independent approval UI are now implemented and tested; see [the configuration contract](numbering-configuration-next.md).

Registry: released document type → initial prefix and padding, versioned by reviewed migrations. Current initial defaults preserve JDR/REV/JE and six digits. Existing sequences retain their prefix and padding forever. New sequence rows use the shared resolver: an approved branch/year override, otherwise the registry default; unsupported types fail closed. No client chooses a document number or trusted actor. Approved branch/year overrides enter that same resolver and guard, not a second numbering engine.

Counter key remains company + branch + document type + calendar year from business date (the historical SQL column is named financial_year). Number format is prefix-year-zero-padded counter. This is not arbitrary fiscal-year numbering. Allocation is inside the source/posting transaction, uses INSERT ON CONFLICT UPDATE locking, and rolls back with any downstream failure. Bigint counters remain strings when formatting. Capacity exhaustion fails visibly; it never wraps or truncates.

Database guards: runtime cannot change sequence identity, format or padding; every UPDATE increments by exactly one. The deferred commit guard requires the newly allocated number to correspond to a source/journal created in that same transaction by the transaction actor. This catches abandoned/forged counter updates. Existing authoritative source/journal immutability and uniqueness remain in force. The database owner remains the trusted migration/recovery principal, not an application login.

Tests precede implementation: registry-driven new-year formatting; stable existing-year formats when defaults change; parallel unique allocation; downstream rollback leaves no used counter; direct decrement/prefix rewrite and abandoned allocation are denied. Configuration evidence additionally covers independent review, exact prior/after audit snapshots, publication racing first allocation, real financial posting/rollback, browser workflow and least-privilege navigation. There is no counter-setting API or approval bypass. A source number is fixed at initial allocation; controlled unposted date revisions do not renumber it.
